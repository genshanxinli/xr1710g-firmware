# 04 · 风险清单与路线图 v0

> 依据 grill 会话已确认的设计树（2026-08-16）撰写。路线图每个里程碑带可测验收；验收数据由 AI 出测试方案/脚本，真机数据人工采集回填（人类最小集）。

## 1. 风险清单与缓解

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **刷错槽位变砖**（系统 ITB / 裸 u-boot.bin 写进 U-Boot 槽） | 高 | SOP 明令禁止；YYH http-uboot 恢复页兜底；NAND 编程器路径写入救砖 SOP（风险自负） |
| R2 | **UBI 布局破坏**（安装器覆盖/刷 W1700K 包） | 高 | 仅用 XR1710G 专属包；UBI 2.0 布局统一；救砖 = YYH 恢复页重装 |
| R3 | **6GHz 无授权使用**（中国 6425–7125MHz 归 IMT/6G 试验） | 中（法律） | 报告明示；社区以 US 监管域低功率固定信道自用；文档标注合规边界 |
| R4 | **CVE-2025-68360 面**（6GHz+offload WED 崩溃） | 中 | 分叉内核含修复 + M2 回归验收（NPU 子验收 ①） |
| R5 | **YYH U-Boot 单点依赖**（社区个人维护，弃坑即固化） | 中 | 备份 YYH 固件镜像 + 串口回刷路径入 SOP；upstream chainloader 作文档备选（一机一路线） |
| R6 | **完全自主分支 rebase 债** | 中 | AI 每日自动合入 upstream；冲突自动处理/上报；补丁两层化（适配层尽量上提 PR） |
| R7 | **驱动快速变化期不稳定**（2026-03 加速失效教训） | 中 | 事件驱动构建留档可回滚；养老固件定位明确不追；每夜产物可对照 |
| R8 | **双 10G 同接 Web UI 失联**（#247242 已知坑） | 低 | 调查修复或文档规避；列入 M2 验证 |
| R9 | **MLO 不成熟** | 低 | 旗舰默认 802.11s 回程，MLO 仅实验项 |
| R10 | **论坛/恩山反爬与登录墙** | 低 | 盯梢清单给出替代路径（Discourse JSON ⩽1 次/分、人工每周回填恩山） |

## 2. 路线图 v0

### M0 · 硬件考据与救砖（与调研报告并行）
- **内容**：下单购机（2 台同型号，按已定风险预算）；拆机/拍照/备份原厂固件分区；UART 全流程验证；**互刷实验**：YYH U-Boot ↔ chainloader 槽位互刷边界、恢复顺序、HTTP 恢复页全流程；采集 NPU 指标盘点基线（`luci-app-airoha-npu`/FlowSense/debugfs 全量抓取脚本由 AI 产出，真机回填）
- **验收**：救砖 SOP 文档（含 YYH 备份与回刷命令序列）+ 原厂固件/分区备份归档 + NPU 指标盘点 v0 版本化清单 + 互刷边界实验报告
- **人类最小集**：拆机、UART 连线、刷机按键

### M1 · 基线可刷
- **内容**：分叉建仓（openwrt main 基线 + XR1710G dts/RTL8261BE/LED/chainloader 适配层，尽量复用/上提 PR #22397）；首次构建成功；YYH 路径刷入实机；双系统（原厂 ↔ 自建）切换验证
- **验收**：两台机器均刷入自建基线并可回退原厂（含 UBI 安装器路径兼容验证）；AI 每日同步循环跑通（连续 7 天无未解决冲突）
- **人类最小集**：真机刷写、回退确认

### M2 · 设备能力全集
- **内容**（v1 验收锁，全部可测）：
  1. 三频 AP + 6GHz 无线回程（802.11s，US 域 ch37/EHT320/WPA3-SAE）
  2. 双万兆灵活 WAN/LAN（含链路聚合/角色切换）
  3. SQM + WireGuard/OpenVPN
  4. DNS 过滤 + USB（若可用）+ LED/按键自定义
  5. Docker/容器 + 应用中心式 LuCI（可后置项，如本期未完成进 M3+）
  6. **NPU 全功能**：四子验收 + ⑤AP/桥接专项 + 指标版本化盘点闭环（详见下文验收矩阵）
- **验收**：逐项测试脚本（iperf3 双 10G 双向近线速、mesh 组网成功率、回程吞吐/时延基准、卸载命中计数、CVE-2025-68360/22061 回归、`tx failed=0`、CPU <5%、一键开关对照）+ 测试报告归档
- **人类最小集**：真机测试数据采集

### M3 · 旗舰版：6GHz 无线回程优化固件 ⭐（旗舰）
- **内容**：以恩山 6GHz 回程优化手法为基础（统一 Mesh ID/SAE/监管域/信道/带宽、客户端交 5GHz、max_inactivity/disassoc_low_ack/performance governor、NPU 延迟探测），叠加本分叉的激进调优层
- **验收**：mesh ESTAB + tx failed=0 实测（跨楼层真实场景）；回程吞吐/时延基准报告；无 UBI/I/O 错误、无 airtime_link_metric_get 报错；温度 52–57°C 常态；连续稳定运行 7×24h 记录
- **人类最小集**：真机测试数据采集

### M4 · 情报体系上线
- **内容**：GitHub Actions 自动跟进循环（每周抓取 #1–#6/#14 + 事件触发构建 + 每夜保底）；跟踪报告 commit 至 `docs/tracking/`；发布帖草稿 AI 生成（恩山/OpenWrt 论坛，人工按键发布）
- **验收**：连续 4 周每周自动产出跟踪报告；上游有动静 → 自动构建 → 自动提请发布闭环跑通；Release 留档 + GPL 合规（构建脚本/configs 公开）
- **人类最小集**：发布按键

## 3. NPU 全功能验收矩阵（版本化）

**词条**（见 CONTEXT.md）：四子验收（① WED/NPU 路径含 6GHz、② PPE 硬 NAT 满载、③ 与 mt76/社区特性共存无降级、④ 可观测可开关）+ **⑤ AP/桥接模式专项**（FlowSense AP 模式流表、WED per-radio 计数、802.11s 回程卸载、逐流/逐客户端命中）+ **指标版本化与实机盘点闭环**。

- 指标来源：mt76 NPU 层提交史（2025-10 → 2026-08）、airoha target 提交史（HW-GRO 2026-06-16、LRO 2026-05-25、PPE MTU L2 开销 2026-06-19）、社区 FlowSense（PPPoE/VLAN/AP 模式/XFRM）、论坛实测（NPU 10Gbps、10G↔Wi-Fi 1.1–1.4Gbps @ CPU 0–1%）、NVD（CVE-2025-68360/22061 等 mt7996 全系）
- **闭环机制**：M0/M2 由 AI 出全量抓取脚本 → 真机跑一遍 → 以实机面板为准滚动收录 → 矩阵版本化（v0/v1/...）；纸上列不全的由机制补全，来源不全的进"改进项"而不进验收
- **核心通过口径**：双 10G iperf3 双向近线速；6GHz 回程 offload 开启 tx failed=0；NPU 转发 ≥10Gbps；10G↔Wi-Fi 场景 CPU <5%；全部 mt7996 相关 NVD CVE 修复在场

## 4. 合规与发布

- 公开仓库 GPL-2.0-or-later；构建脚本/configs/补丁集全公开（可复现构建 = GPL 合规）
- 发布节奏：事件驱动（airotarget/mt76/hostapd/PR #22397 有动静）+ 每夜保底 + 里程碑 tag
